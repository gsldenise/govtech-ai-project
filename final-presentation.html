Module 1
Skill file
Role

An applicant self-serve guide where applicants answer situational questions about themselves (renewal or first-time, for whom, etc.), review what they need to bring, and understand whether their documents match. The guide surfaces only what is relevant to their scenario—not generic passport guidance. It does not validate documents, make decisions, or confirm acceptance.

Task

Applicant answers 3–4 branching questions about their own situation (self-renewal vs child renewal, etc.). Based on their answers, return a tailored one-screen summary of requirements. Applicant uses this to gather and verify documents before uploading. If applicant's situation falls outside known scenarios, surface a clear message and offer to escalate to ICA.

Module 3
AI PRD
Problem and user

User: ~520,000 applicants per year uploading passport photos; ICA officers reviewing submissions.

The problem:
- 100% of ICA returns stem from photo non-compliance (wrong dimensions, background, expression, clarity)
- Applicants don't know photo requirements upfront and often submit multiple times
- ICA officers waste time rejecting photos that fail basic checks
- Applicant experience: rejection + resubmit + 6-day additional wait = frustration

The opportunity:
- Catch non-compliant photos *before* ICA submission (client-side, in real-time)
- Return specific feedback so applicants know exactly what to fix
- Reduce photo-related returns from 28% to <15%, saving ICA ~6 days per applicant

Success looks like:
- Applicant uploads photo → agent validates in ~1–2 seconds
- Applicant sees: ✓ Photo passes (proceed) OR ✗ Photo fails + specific reason (e.g., "Face not centered; move to middle of frame")
- Officer sees FLAG cases (75–89% confidence) with structured notes for final decision
- Return rate on photo drops from 28% to <15%

Module 4
Agent control panel
What it is doing

In one sentence: The agent receives an uploaded photo, validates it against a 10-point ICA checklist in ~1–2 seconds, and returns PASS (proceed to submit), FLAG (officer reviews), or FAIL (applicant resubmits) with specific feedback.

The job:
1. Verify file is readable (not corrupted, wrong format)
2. Run 10-point checklist: 4 strict geometric checks + 5 ML-simulated checks + 1 EXIF check
3. Assign confidence score (0–100%)
4. Decide outcome: PASS (90%+), FLAG (75–89%), FAIL (<75%)
5. Return feedback in applicant's language with guidance on what to fix
6. Create officer note if FLAG (for officer review workflow)
7. Log validation event anonymously (no PII, no photo stored)

Success: Applicant knows exactly why photo passed or failed; can resubmit if needed; officer gets structured note for borderline cases.

Rules of engagement

File format unsupported: ✅ Reject, —, Pre-flight; no submission
File too large: ✅ Reject, —, Pre-flight; no submission
File corrupted: ✅ Reject, —, Pre-flight; no submission
Dimensions 400×514 exact: ✅ FAIL if not, —, Strict; no tolerance
Background white: ✅ FAIL if not, —, Strict; deterministic
All 10 checks pass: ✅ PASS, —, Submit directly
1 ML check fails (75–89% confidence): ✅ FLAG, ✅ Reviews + decides, Borderline; applicant may resubmit or wait
2+ checks fail (<75% confidence): ✅ FAIL, —, User resubmits
Suspected deepfake / tampering: ✅ Flag + escalate, ✅ Approves/rejects, Out of scope for agent
Multiple faces, unclear primary: ✅ Flag + escalate, ✅ Clarifies, Ambiguous; need human judgment
Applicant submits PII: ✅ Reject, —, Privacy guardrail; re-upload
Application eligibility: —, ✅ Decides, Not agent's role
Special circumstances override: —, ✅ Decides, Human judgment only

Module 5
Human eval rubric
What I score

Scoring arithmetic:
- Binary (YES/NO) dimensions: 1 point if YES, 0 if NO
- Dim 1 (Accuracy): YES = 1 pt, NO = 0 pts
- Dim 3 (Privacy): YES = 1 pt, NO = 0 pts
- Dim 5 (Determinism): YES = 1 pt, NO = 0 pts
- Dim 6 (Guardrails): YES = 1 pt, NO = 0 pts
- Scale (1–5) dimensions: raw score (e.g., 4 = 4 pts, 3 = 3 pts)
- Dim 2 (Clarity): 1–5
- Dim 4 (Escalation): 1–5
- Case total = Dim1 + Dim2 + Dim3 + Dim4 + Dim5 + Dim6
- Min: 0 (all NOs on binary + 1s on scales) = 2/13
- Max: 4 (all YESs on binary + 5s on scales) = 13/13
- Option B pass: 13 cases, sum ≥ 161/169 (95% pass rate) OR explicitly: deal-breakers 4/4 + non-deal-breakers ≥8/9

Deal-breaker dimension mapping:
- Case 4: Dim 1 only (if Dim 1 = NO, case FAILS)
- Case 10: Dim 3 + 6 (if either = NO, case FAILS)
- Case 12: Dim 6 only (if Dim 6 = NO, case FAILS)
- Case 13: Dim 4 + 6 (if either = NO, case FAILS)

Module 12

How I’ll know it’s working

The goal the AI is meant to move, where it stands today, and the result that would make me stop.

The goal

Agent consistently validates passport photos to ICA spec, reduces false rejections (<10%), and applicants understand outcomes.

Baseline

- All 13 cases pass against fixed CLAUDE.md (version commit 8177db6)
- Option B met: Deal-breakers 4/4 PASS, other metrics 100% PASS (exceeds 85% threshold)
- No pattern issues: All dimensions balanced (no Clarity always 2/5, no Escalation always 1/5)
- Grading consensus: All 3 calibration cases (1, 9, 13) scored exactly as rubric (0 disagreements)

Target and review date

- Option B maintained: At least 11/13 cases PASS; deal-breakers 4/4 PASS; ≥85% on other metrics
- Engagement metric: ≥25% of test users complete end-to-end validation
- Clarity metric: ≥75% of users can describe what photo checks mean (post-test survey)
- No deal-breaker surprises: Cases 4, 10, 12, 13 pass every run
- Officer satisfaction: >80% of FLAG cases have actionable officer notes (post-test survey)

Usage metric

Weekly accuracy trend:
```
Week 1 (baseline): 13/13 PASS
Week 2 (monday): 13/13 PASS
Week 3 (monday): 13/13 PASS
Week 4 (usability test): [score both Auto and Confirm groups]
```

- Did CLAUDE.md rules change? (check git diff)

Stop line

Stop deployment if ANY of these occur:
1. Deal-breaker case fails (Case 4, 10, 12, or 13 scores FAIL on its critical dimension)
2. Option B threshold breached (deal-breakers 4/4 still pass, but other metrics drop below 85%)
3. Systematic grading error (weekly spot check finds >1 dimension scored incorrectly on same case)
4. Agent rule change without re-eval (CLAUDE.md changed but 13 cases not re-run before deployment)

Escalation: Any stop line → Engineering Lead notifies Product Manager + Sponsor within 1 hour.
